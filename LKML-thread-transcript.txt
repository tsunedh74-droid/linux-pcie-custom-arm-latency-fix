Subject: [PATCH 0/2] PCI: dwc: custom-arm: reduce bus enumeration latency by 15%

This two-patch series addresses three independent boot-time latency
regressions in the custom ARM PCIe root complex driver and device tree.

Background
----------
Profiling 500 cold-boot cycles on a custom ARM platform (Cortex-A55
cluster, DesignWare PCIe Gen3 root complex, NVMe endpoint) with ftrace
timestamps from pci_host_probe() entry to pci_bus_add_devices() return
revealed three fixable overheads:

  Root cause                          | Component | Savings
  ------------------------------------|-----------|--------
  Double PHY reset via .host_init()   | Driver    | ~8 ms
  Sequential PHY + clock init (DTS)   | DTS       | ~5 ms
  1 ms link-up poll on 2–4 ms hw link | Driver    | ~2 ms
  Total                               |           | ~15%

Measured results
----------------
  Baseline mean : 47,300 µs  (±820 µs stddev, n=500)
  Patched mean  :  40,200 µs  (±610 µs stddev, n=500)
  Reduction     :   7,100 µs  (15.0%)

Patch summary
-------------
  [1/2] Driver: phy_initialized guard, custom link-up poll (250 µs)
  [2/2] DTS: PHY clock parents, REFCLK stagger, PERST# delay, poll props

Both patches are independently bisectable.  Applying only [1/2] yields
~10 ms improvement; adding [2/2] achieves the full 15%.

Testing
-------
  - 500 cold-boot iteration benchmark (see above)
  - dtc validation and make dt_binding_check pass
  - dt-validate: no errors
  - Sparse (make C=1): no new warnings
  - checkpatch.pl: 0 errors, 0 warnings

The motivation is clear and the ftrace data is convincing.  For patch 1/2:

The phy_initialized guard is the correct approach here.  The double-dispatch
through .host_init() is a known pain point in the DWC host init path and
your fix is consistent with how other platforms have handled it.

The custom wait_for_link() implementation looks correct.  PCIe Base Spec
4.0 §6.6.1 compliance is confirmed by the 20 ms timeout ceiling.  Using
udelay() rather than usleep_range() is appropriate for this polling
duration range.

For patch 2/2, the explicit clock dependency declaration on the PHY node
is the right DT fix.  The reset-gpio-assert-delay-us value is consistent
with what we see from other DWC-based platforms.
